# Section to plan correspondence diagnostics

Open `section-correspondence.html` in a planning pilot or collection output. It
retains original drawing-reference circles and all contextual floor-plan
component hypotheses for each measured section profile. The JSON receipt pins
each input page, profile, component, scale trial, drawing code and literal sheet
reference. Desktop job details show the contextual-pair and ambiguous-profile
counts. Red curves in original-page overlays reproduce the reference circles.

Reference extraction supports four-digit sheet numbers inside a closed,
approximately circular source path made of four cubic Beziers. Original control
points, paint sequence, native coordinates and source glyph screens are retained.
Every nearby outside numeric index with the same text direction is retained;
multiple indices or failed glyph screens withhold the index assignment. The
three-radius search is a layout hypothesis. No nearest number, filled-corner
assumption, clipping repair, marker bearing or section-cut semantics is inferred.
Four-digit sheet values retain leading zeros.

For each unassigned profile, the comparison requires a unique visible drawing
code, a shared drawing series, a visible literal reference to the section sheet,
matching printed state, a complete component/measurement inventory and the same
printed component noun. It retains every contextual component and every nominal
scale trial. Both oriented plan spans are compared with the section's horizontal
span, at a fixed default diagnostic tolerance of 0.25 m. This does not establish
the cut axis, handle oblique cuts, rank candidates or resolve physical identity.
Mismatches remain visible. Even one size-compatible candidate stays unassigned.
Numeric view indices are never mapped to lettered sections or caption order.

The Woodcutters development replay uses previously inspected cached originals
for SMD/2024/0136. It recovers four reference markers on the proposed floor plan
and four on the existing floor plan. Proposed markers point to sheet 0301 with
outside indices 4, 2, 1 and 3. The target sheet's Section A-A and B-B captions are
unnumbered. All three proposed plan boundary hypotheses remain contextual rivals
for the one measured Container profile in Section A-A. Their short spans are
similar; that does not identify a physical component. The earlier two printed-size
agreements and one mismatch remain unchanged.

Per-page marker defaults are 128 markers, 500,000 work checks and two MB of
evidence. Reviews allow 512 distinct pages, 128 profiles, 8,192 comparisons and
eight MB of output. Limits and the width tolerance can only be reduced.
Work/count/byte exhaustion clears the entire corresponding result, cancellation
propagates, identical page receipts deduplicate and conflicting or stale evidence
is rejected. Incomplete upstream inventories are retained as page-level holds;
they cannot supply successful component comparisons. This is a context inventory,
not a claim that all physical components have been discovered.

Pilot and collection contracts pin this implementation. Both automatic batches
and verified restarts export the diagnostics, and existing drawing analysis is
invalidated when implementation bytes change. A synthetic seven-document,
two-batch replay deliberately retains 98 contextual pairs rather than guessing
which repeated same-series drawing represents the same component.

The next reconstruction gate is a source-supported section-cut-to-component
link, followed by checked scale, exterior-wall interpretation and a local ground
datum with supported height endpoints. This feature assigns no physical height,
generates no 3D shell or world blocks and produces no reviewed training labels or
neural weight updates. The replay is not an independent accuracy benchmark.
