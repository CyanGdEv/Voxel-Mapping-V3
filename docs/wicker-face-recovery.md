# Wicker face recovery and glyph visibility

The park job now has a face-association stage. It checks native callout text against the rendered source, recovers exact enclosed straight-line faces, preserves polygon interiors, and records the original image/pixel location when a callout depends on raster drawing content. It produces evidence rather than automatically placed geometry.

## Glyph screen

The comparison supports black, fully opaque ASCII text in cardinal directions. It resolves a unique original font resource by native span name. Embedded fonts are reused from their exact bytes, with a recorded SHA256; an unembedded Helvetica Type1 source can use the standard base font. Ambiguous or unsupported font resources, optional layers, unknown transforms, non-ASCII text, opacity changes and offset cropboxes are withheld.

An isolated reference is drawn at the original positions and compared to a source clip at six pixels per PDF point. Every non-space glyph needs at least three core ink pixels and at least 99% pixel support, allowing one pixel of raster-position tolerance. A surrounding ring also checks unexpected dark pixels, so a black rectangle covering the text cannot pass merely by matching its ink. A white mask erasing letters fails the glyph support test. Each raster is bounded to one million pixels, 500 characters and a two-megabyte embedded font.

This is a raster consistency screen, not proof of semantic identity, approval/as-built state or component visibility. `visibility_verified` stays false. Material authenticity, revision state and world placement remain independent gates. Page rotation is restored after every comparison, and original PDFs are not saved or rewritten.

## Face and raster association

Only exact enclosed linework faces from the existing source-traceable recovery adapter are considered. No endpoint snapping, gap filling, roof inference or polygon union is introduced. Every containing face is retained; nested enclosures remain ambiguous instead of selecting the smallest. Arrow points on an edge or inside a polygon hole are not snapped into the face. Interior rings are retained as opening candidates without certifying that they are physical openings.

A unique source face is still an unverified component candidate. View identity, scale, height/depth, openings, actual materials and drawing state must be established before reconstruction. Raster dependencies preserve the native image placement affine, original image hash and anchor pixel, rather than replacing the component with the image rectangle.

## Replay and park integration

Use the exact source PDFs and the document list generated by `scripts/replay_wicker_annotations.py`:

```sh
python -m voxel_mapper.drawing_faces \
  --documents /path/to/wicker-annotation-documents.json \
  --output /path/to/fresh-face-review
```

Outputs:

- `face-associations.jsonl`: each anchor, its original callout decision, glyph result, candidate faces and raster dependencies.
- `face-candidates.jsonl`: exact enclosed linework polygons with original source-edge provenance.
- `page-reviews.jsonl`: full glyph comparisons and page extraction/recovery receipts.
- `face-report.json`: summary, backend/version contract and output hashes.

Add this to a park job:

```json
{"drawing_faces":{"enabled":true,"documents":"documents.json","max_pages":10000}}
```

The reconstruction/compile stage records this evidence and pins input/output hashes. It does not append face candidates or raster rectangles to geometry feeds. With no accepted feature feeds, the job remains `awaiting_normalized_geometry`. Completed runs require matching document bytes, versions and output hashes; interrupted runs require a fresh directory.

The retained report and associations are in `evidence/wicker-face-recovery-report.json` and `wicker-face-associations.jsonl`; full candidate geometry and pixel checks are in `wicker-enclosed-face-candidates.jsonl` and `wicker-face-page-reviews.jsonl`.

## Raster adapter first stage

`material-anchor-faces-v2` now runs `raster-anchor-regions-v1` on glyph-screened material anchors. It reconstructs an image-only grayscale atlas at two pixels per PDF point, in unrotated page coordinates. Cardinal rotations and horizontal reflections are replayed explicitly; overlapping image occurrences retain source paint order. Each occurrence retains its original image hash, affine and xref. Native text and vector annotation leaders are excluded. Source clipping and optional-layer visibility remain unverified, so the atlas is evidence, not a certified rendering of physical components.

The shop and maintenance sheets each reconstruct 85 image occurrences. Coarse ink-proximity grouping produces six shop and seven maintenance artwork review windows. These include unrelated artwork such as material swatches and logos: their rectangles are neither certified drawing views nor building faces. Each material anchor retains all containing review-window IDs, without nearest-window assignment.

The region screen uses four-connected pixels at fixed gray thresholds 176, 192, 208 and 216. An anchor must remain inside a broad, bounded region at every threshold, with at least 98% intersection-over-union stability. Dark anchor hits, narrow strips, window-edge leaks, disconnected intersections and excessive boundary complexity are withheld. The common pixel region is polygonized without gap closing or inferred boundary repair; interior rings survive as unverified opening candidates. This screen does **not** remove hatch strokes or distinguish physical boundaries from shadows.

Budgets limit the atlas to 20 million pixels, 1,000 image occurrences, 100 million total source pixels and 100 MB total extracted image bytes. Individual images are bounded to 20 million pixels and 20 MB. Region windows have a maximum radius of 160 PDF points and polygons are limited to 4,096 vertices. Cropped pages, skew transforms, inline images and masks receive explicit withheld receipts. NumPy, SciPy, rasterio and MuPDF versions enter the completed-run contract. Install the `planning` extra for SciPy and MuPDF.
